# Risk Center: เอกสารสูตรและแหล่งข้อมูล

เอกสารนี้อธิบายว่า Risk Center ของ Jatso (หุ้นสหรัฐ, พอร์ตจำลอง) ใช้ข้อมูลจากไหน คำนวณอย่างไร และอะไรที่ไม่ได้ทำ
เขียนจากโค้ดใน `api/stocks/` (วิธีคำนวณเวอร์ชัน `stock-risk/1.0.0`) ถ้าแก้สูตรในโค้ด ต้องแก้เอกสารนี้และเพิ่มเลขเวอร์ชัน `METHOD_VERSION` ใน `risk_engine.py`

> ตัวชี้วัดทั้งหมดอธิบายอดีตของพอร์ตนี้เท่านั้น ไม่ใช่การพยากรณ์และไม่ใช่คำแนะนำการลงทุน

## 3. สมุดบัญชีและ NAV

- **วันที่ของรายการ (session date):** ซื้อขายก่อน 16:00 ET นับเป็นวันนั้น ตั้งแต่ 16:00 ET นับเป็นวันทำการถัดไป
- **ปรับ split:** รายการถูกปรับเป็นหน่วยหลัง split ถ้า ex-date มากกว่าวันที่ (ET) ของรายการ: `qty × ratio`, `price ÷ ratio`
- **เงินสด:** `cash_t = เงินตั้งต้น + Σ (ขาย: qty×price − fee, ซื้อ: −(qty×price + fee))` ของรายการที่ session date ≤ t
- **NAV:** `NAV_t = cash_t + Σ_i q_i,t × P_i,t` รายการของวัน t ถูกบันทึกก่อนตีมูลค่าวัน t
- **ราคาที่ขาด:** เติมราคาปิดล่าสุดไปข้างหน้า (forward-fill) ได้ไม่เกิน 5 วันทำการ เกินนั้นหรือไม่มีราคาเลย NAV วันนั้นเป็น `null` และรายงานเป็น `incomplete`
- **ปฏิทิน:** ใช้วันซื้อขายของ S&P 500 ถ้าไม่มีดัชนี ใช้ปฏิทินรวมของหุ้นที่ถือ (เตือน `calendar_from_holdings`)
- **ฐานของช่วง:** วันทำการสุดท้ายที่ไม่เกิน 1 ปีก่อนวันล่าสุด ถ้าพอร์ตเริ่มหลังนั้น ใช้วันก่อนเริ่มพอร์ต (เตือน `portfolio_younger_than_period`)
- **ต้นทุน:** ต้นทุนเฉลี่ย (average cost) ค่าธรรมเนียมไม่ถูกนับเข้าต้นทุน แยกบันทึกต่างหาก
- **ตรวจความถูกต้อง:** ขายเกินจำนวนที่ถือ = `ledger_integrity_error` · เงินสดจากสมุดไม่ตรงบัญชีเกิน 0.01 = เตือน `cash_reconciliation_mismatch` · ราคาซื้อขายนอกช่วง low/high ของวัน (±1%) = เตือน `trade_price_outside_daily_range`

## 4. ผลตอบแทน

| ตัวชี้วัด | สูตร |
|---|---|
| ผลตอบแทนรายวัน | `r_t = NAV_t / NAV_t−1 − 1` (ผลตอบแทนถ่วงเวลา เพราะไม่มีกระแสเงินภายนอก ราคาเป็นราคา ไม่รวมปันผล หลังหักค่าธรรมเนียม) |
| ผลตอบแทนรวม | `∏(1 + r_t) − 1` |
| ส่วนเกิน (active) | `R_p − R_b` แสดงเป็นจุดเปอร์เซ็นต์ (pp) |
| Relative wealth | `(1 + R_p) / (1 + R_b) − 1` |
| CAGR | `(1 + R)^(365.25 / D) − 1` เมื่อ D (วันปฏิทิน) ≥ 365 ไม่งั้นไม่คำนวณ |
| รายเดือน | ทบต้นผลตอบแทนรายวันในเดือนปฏิทิน เดือนแรกและเดือนสุดท้ายอาจไม่เต็มเดือน |

อัตราปลอดความเสี่ยงรายวันของวัน t ใช้ผลตอบแทน 3M Treasury ที่สังเกตได้ล่าสุด ณ วัน t−1 (ถ้าห่างเกิน 7 วัน ถือว่าไม่มี Sharpe/Alpha): `r_f,d = (1 + y)^(1/252) − 1`

## 5. ตัวชี้วัดปรับตามความเสี่ยง

ใช้ 252 วันทำการต่อปี (`SQRT_T = √252`) ส่วนเบี่ยงเบนมาตรฐานเป็นแบบตัวอย่าง (หาร N−1)

| ตัวชี้วัด | สูตร | ข้อมูลขั้นต่ำ |
|---|---|---|
| ความผันผวนรายปี | `SD(r_p) × √252` | 20 วัน |
| Tracking error | `SD(r_p − r_b) × √252` | 20 วัน |
| Sharpe | `mean(r_p − r_f) / SD(r_p − r_f) × √252` | 60 วัน |
| Downside deviation | `√(Σ min(r − MAR_d, 0)² / N) × √252`, MAR = 0 | 60 วัน |
| Sortino | `mean(r_p − MAR_d) / DD_d × √252` | 60 วัน |
| Information ratio | `mean(r_p − r_b) / SD(r_p − r_b) × √252` | 60 วัน |
| Beta | `Cov(r_p, r_b) / Var(r_b)` | 60 วัน |
| R² | `Corr(r_p, r_b)²` | 60 วัน |
| Downside beta | Beta เฉพาะวันที่ `r_b < 0` | 20 วัน (ตัวอย่างน้อยถ้า < 60) |
| CAPM: Beta, Alpha | OLS `(r_p − r_f) = α + β(r_b − r_f) + ε` · Alpha รายปี `= α_d × 252` | 60 วัน |
| t-stat ของ Alpha | `α_d / SE(α_d)` | 60 วัน |
| Treynor | `mean(r_p − r_f) × 252 / β_capm` | 60 วัน |
| Appraisal ratio | `α_d / σ_ε × √252` | 60 วัน |
| Calmar | `CAGR / |MDD|` | ต้องมี CAGR (ครบ 1 ปี) และมี drawdown |
| Up/Down capture | `GeoMean(r_p \| r_b > 0 หรือ < 0) / GeoMean(r_b \| วันเดียวกัน)` | 10 วัน |
| สัดส่วนวันที่ชนะดัชนี | `#(r_p > r_b) / N` | 20 วัน |

## 6. Drawdown และความเสี่ยงขาลง

- **Drawdown:** `DD_t = W_t / max_{s≤t} W_s − 1` โดย `W` คือความมั่งคั่งสะสมจากผลตอบแทนรายวัน รายงานค่าปัจจุบัน ค่าลึกสุด ช่วงลึกสุด (ยอดเดิม → จุดต่ำสุด → วันฟื้นตัว) และช่วงจมน้ำนานสุด (วันทำการ)
- **VaR 95% (1 วัน):** `−Q₀.₀₅(r)` ควอนไทล์ประวัติศาสตร์แบบ type-1 (inverted CDF) ต้องมี 60 วัน
- **ES 95% (1 วัน):** `−mean(r | r ≤ Q₀.₀₅)` ต้องมี 60 วัน
- **ค่าสุดขั้ว:** วัน/สัปดาห์ (ISO)/เดือนที่แย่ที่สุด
- **Rolling:** หน้าต่าง 63 วันทำการ คำนวณความผันผวน, Beta, Sharpe ตามสูตรด้านบนในแต่ละหน้าต่าง
- **การกระจายผลตอบแทนรายวัน:** ฮิสโตแกรมความกว้างเท่ากัน จำนวนช่อง ≈ √n (5–20) แสดงเมื่อมีผลตอบแทนอย่างน้อย 20 วัน พร้อมเส้น VaR/ES

## 7. การกระจุกตัว, ความเสี่ยงรายตัว, Stress test

- **น้ำหนัก:** `w_i = MV_i / NAV` (เงินสดเป็นส่วนที่เหลือ) และ `w_i,equity = MV_i / Σ MV`
- **HHI** `= Σ w_i,equity²` (น้ำหนักในส่วนหุ้น ไม่รวมเงินสด) · **จำนวนหุ้นเทียบเท่า** `= 1 / HHI` · **Top 1/3/5** = ผลรวมน้ำหนักในส่วนหุ้นของตัวใหญ่สุด
- **อุตสาหกรรม:** รวมมูลค่าตลาดตาม Finnhub industry (ไม่ใช่ GICS) หุ้นที่ไม่มีข้อมูลรวมเป็น `Unknown`
- **การแยกความเสี่ยง:** ความแปรปรวนร่วมตัวอย่างจากผลตอบแทนรายวัน × 252 ใช้น้ำหนักปัจจุบันคงที่ตลอดช่วงอดีต (เงินสดความแปรปรวน = 0)
  - `σ_p = √(wᵀΣw)`
  - `MCR_i = (Σw)_i / σ_p` (ความผันผวนพอร์ตเปลี่ยนเท่าไรต่อน้ำหนักที่เพิ่ม)
  - `CCR_i = w_i × MCR_i` · สัดส่วนความเสี่ยง `= CCR_i / σ_p` (รวมกันได้ 100%)
  - Diversification ratio `= Σ w_i σ_i / σ_p` · สหสัมพันธ์เฉลี่ยของทุกคู่
  - ต้องมี 60 วันที่ตรงกัน หุ้นที่ราคาในช่วงไม่ครบถูกตัดออกและแจ้งใน `excluded` (สถานะกลายเป็นตัวอย่างน้อย)
- **Beta รายตัว (ใช้ใน stress):** OLS slope เทียบดัชนี ต้องมีประวัติครบทั้งช่วง
- **Stress test (สถานการณ์สมมติ ไม่ใช่การพยากรณ์):** `P&L_i = MV_i × shock_i`
  - ลำดับความสำคัญของ shock: ระบุรายตัว > ระบุรายอุตสาหกรรม > `β_i × market_shock`
  - shock ต่ำสุด −100% (ตำแหน่งซื้อขาดทุนเกินมูลค่าไม่ได้)
  - ตัวที่ไม่มี shock และไม่มี beta ถูกข้ามและแจ้งใน `skipped` · ผลรวมแยกตามอุตสาหกรรมนับเฉพาะตำแหน่งที่คำนวณได้
  - **ไม่ได้จำลอง** การเปลี่ยนความสัมพันธ์หรือความผันผวนในภาวะวิกฤต

## 8. ที่มาของผลตอบแทน (Attribution)

เป็นแบบบางส่วน: ส่วนร่วมรายตัวเท่านั้น (ไม่ใช่ Brinson)

- **ส่วนร่วมรายตัว:** `c_i = Σ_t W_t−1 × q_i,t−1 × (P_i,t − P_i,t−1) / NAV_t−1` โดย `W_t−1 = NAV_t−1 / NAV_0` (ถ่วงเชื่อมแต่ละวัน)
- **ซื้อขายจริงเทียบราคาปิด (execution):** `Σ_trades ±q × (P_close − p_fill)` ในวันที่ซื้อขาย เชื่อมด้วยตัวถ่วงเดียวกัน
- **ค่าธรรมเนียม:** `−Σ fee` เชื่อมด้วยตัวถ่วงเดียวกัน
- **ผลรวม:** ส่วนร่วมรายตัว + execution + ค่าธรรมเนียม = ผลตอบแทนพอร์ต ระบบคืนค่า `sum_check` (residual, tolerance 1e-9) ให้ตรวจ ไม่ได้สมมติว่าตรง
- **Cash drag (ข้อมูลประกอบ ไม่รวมในผลรวม):** `Σ_t W_t−1 × (−w_cash,t−1) × r_invested,t` โดย `r_invested,t` คือผลตอบแทนของส่วนหุ้นที่ถืออยู่ต้นวัน ค่าลบ = เงินสดทำให้ผลตอบแทนต่ำกว่าถ้าลงทุนเต็ม ค่าบวก = เงินสดช่วยลดการขาดทุน (เงินสดไม่มีดอกเบี้ย)
- **ส่วนร่วมราย sector:** ผลรวมส่วนร่วมรายตัวตามอุตสาหกรรม (รวมตัวที่ขายแล้ว) รวมกันเท่ากับผลรวมส่วนร่วมรายตัว
- **Realized / Unrealized P&L (ดอลลาร์สะสมตั้งแต่ซื้อครั้งแรก, ต้นทุนเฉลี่ย):** `Realized = Σ (ราคาขาย − ต้นทุนเฉลี่ย) × qty` · `Unrealized = (ราคาล่าสุด − ต้นทุนเฉลี่ย) × qty` · `รวมสุทธิ = Realized + Unrealized − ค่าธรรมเนียม` ตรวจให้ตรงกับ `NAV ล่าสุด − เงินตั้งต้น` ภายใน 0.01 USD ถ้าตัวใดไม่มีราคาล่าสุดจะไม่เดาและไม่ตรวจ ตัวเลขนี้เป็นเงินดอลลาร์สะสมตั้งแต่เริ่ม ไม่ใช่ผลตอบแทนถ่วงเวลา 1 ปี จึงเทียบกันตรง ๆ ไม่ได้

## 9. ลิมิตและการเตือน (Alerts)

การประเมินเกิดเมื่อผู้ใช้กด "ประเมินตอนนี้" (`POST /alerts/evaluate`) ไม่ใช่ตามราคาสดต่อเนื่อง

| ชนิด | เงื่อนไขเปิด | ข้อมูลขั้นต่ำ |
|---|---|---|
| `drawdown` | drawdown ปัจจุบัน ลึกกว่าลิมิต | 20 วัน |
| `single_weight` | น้ำหนักหุ้นตัวใดต่อ NAV > ลิมิต (แยกรายตัว) | – |
| `hhi` | HHI > ลิมิต | – |
| `low_cash` | เงินสดต่อ NAV < ลิมิต | – |
| `sector_weight` | น้ำหนัก sector ต่อ NAV > ลิมิต (แยกรายอุตสาหกรรม) | ต้องรู้ sector |
| `daily_loss` | ขาดทุน NAV ของวันซื้อขายล่าสุด > ลิมิต | 2 จุด NAV |
| `volatility` | ความผันผวนรายปี > ลิมิต | 20 วัน |
| `tracking_error` | tracking error รายปี > ลิมิต | 20 วัน |
| `stale_data` | ข้อมูลเก่า (เกิน 4 วันปฏิทินนับจากวันล่าสุด) หรือบางตัวไม่มีราคา | เปิดเสมอ ไม่มีลิมิต |

**กติกาสำคัญ**

- **ข้อมูลไม่พอ = ข้าม** ไม่เปิดและไม่ปิด alert เก่า (ไม่สรุปว่าปลอดภัยจากข้อมูลที่ไม่ครบ)
- **sector:** ถ้ามีหุ้นที่ไม่ทราบ sector จะเปิด alert ให้เฉพาะ sector ที่รู้ชัด (เป็นค่าขั้นต่ำ) แต่ไม่ปิด alert เก่า เพราะยืนยันไม่ได้ว่าไม่เกิน และจะเรียก Finnhub เฉพาะเมื่อผู้ใช้ตั้งลิมิต sector
- **ระดับความรุนแรง:** `critical` เมื่อค่าที่วัดได้เลยลิมิตตั้งแต่ 1.25 เท่า (`low_cash`: ต่ำกว่าลิมิต ÷ 1.25) ไม่งั้น `warning` · `stale_data` เป็น `critical` เมื่อเก่าตั้งแต่ 8 วัน (2 × 4)
- **วงจร:** เปิด → อัปเดตค่าเมื่อประเมินซ้ำ → ปิดเมื่อเงื่อนไขหาย แต่ละ (ชนิด, หุ้น/sector) มี alert active ได้ 1 รายการ (unique index) · ถ้าความรุนแรงเพิ่มขึ้น สถานะ "รับทราบ" ถูกล้าง
- **รับทราบ (acknowledge):** ผู้ใช้กดรับทราบได้เฉพาะ alert ของตัวเองที่ยัง active ไม่ปิด alert
- **ค่าเริ่มต้น:** ผู้ใช้ที่ยังไม่เคยบันทึกลิมิตเลยใช้ค่าเริ่มต้น (ตัวอย่างทั่วไป ไม่ใช่คำแนะนำ) ผู้ใช้ที่มีแถวลิมิตแล้ว ค่าว่าง (null) = ปิดลิมิตนั้น

| ลิมิต | ค่าเริ่มต้น |
|---|---|
| Drawdown สูงสุด | 20% |
| หุ้นตัวเดียวสูงสุด | 25% |
| HHI สูงสุด | 0.40 |
| เงินสดขั้นต่ำ | 5% |
| Sector สูงสุด | 40% |
| ขาดทุนรายวันสูงสุด | 3% |
| ความผันผวนสูงสุด (รายปี) | 30% |
| Tracking error สูงสุด (รายปี) | 10% |

## 10. สถานะข้อมูลและป้ายเตือน

ทุกตัวชี้วัดคืนค่า `{value, status, unit, formula, n_obs, reason}`

| `status` | ความหมาย |
|---|---|
| `ok` | คำนวณได้ ข้อมูลเพียงพอ |
| `limited_sample` | คำนวณได้ แต่ข้อมูลน้อยกว่า 250 วัน (ตัวชี้วัดที่ใช้เกณฑ์นี้) ตัวเลขแกว่งง่าย |
| `insufficient_data` | ข้อมูลไม่พอ ไม่แสดงตัวเลข แสดงความคืบหน้า "มีข้อมูล x จาก y วัน" |
| `undefined` | นิยามไม่ได้ (เช่น ความแปรปรวนของดัชนีเป็นศูนย์) |
| `unavailable` | ไม่มีข้อมูลต้นทาง |

ค่า `meta.data_status` ของรายงาน: `ok`, `ok_with_warnings`, `no_account`, `no_activity`, `insufficient_data`, `incomplete`, `unavailable`, `ledger_integrity_error`

รหัสเตือน (`meta.warnings`):

- **ข้อมูลต้นทาง:** `prices_unavailable`, `benchmark_unavailable`, `risk_free_unavailable`, `splits_unavailable`, `unofficial_price_source`, `split_adjustment_incomplete`, `risk_free_gap`, `calendar_from_holdings`, `sector_unavailable`
- **สมุดบัญชี/NAV:** `missing_price`, `stale_price_beyond_limit`, `position_unpriced`, `portfolio_younger_than_period`, `trades_after_last_close`, `trade_price_outside_daily_range`, `cash_reconciliation_mismatch`, `ledger_invalid`, `too_many_symbols`
- **Attribution:** `attribution_unavailable`, `attribution_residual`

ความสดของข้อมูล: `meta.freshness = stale` เมื่อราคาล่าสุดเก่ากว่า 4 วันปฏิทิน

## 11. ความปลอดภัย

- ทุก endpoint ยืนยันตัวตนด้วย JWT (HS256) ใช้อีเมลจาก `sub` เป็นตัวกรองข้อมูล ไม่รับอีเมลจากฝั่งผู้ใช้
- จำกัดอัตราต่อผู้ใช้: endpoint ทั่วไป 30 ครั้ง/นาที · ประเมิน alert 5 ครั้ง/นาที · แก้ลิมิต/รับทราบ 20 ครั้ง/นาที
- การแก้ลิมิตบันทึกใน `audit_log` (ค่าเดิม ค่าใหม่ ผู้แก้) ถ้าเขียน audit ไม่สำเร็จ ระบบแจ้งในผลตอบกลับ
- คีย์ผู้ให้บริการข้อมูลอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น
- ตารางสำรองจากการ migrate (`*_bak_20261027`) เปิด RLS ไว้ ควรลบเมื่อไม่ต้องใช้

## 12. สิ่งที่ยังไม่ได้ทำ / ข้อจำกัดที่ต้องรู้

| หัวข้อ | สถานะ |
|---|---|
| Brinson (allocation / selection / interaction) และเทียบ sector กับ S&P 500 | **ไม่ทำ** ไม่มีน้ำหนัก sector ของดัชนี บรีฟห้ามเดา |
| Factor exposure | **ไม่ทำ** ไม่มีข้อมูล factor |
| Stress: การเปลี่ยน correlation / volatility | **ไม่ได้จำลอง** |
| กฎเตือน earnings | **ยังไม่ทำ** ยังไม่ยืนยันแหล่งข้อมูลปฏิทิน earnings |
| Corporate actions นอกจาก split | **ยังไม่จัดการ**: เปลี่ยนชื่อสัญลักษณ์, หุ้นถูก delist, spin-off, ควบรวม ระบบไม่ตีมูลค่าให้และไม่เดา ถ้าหุ้นที่ถืออยู่ไม่มีราคาเกิน 5 วันทำการ NAV วันนั้นเป็น `null` และรายงานเป็น `incomplete` แต่จะแจ้งสาเหตุที่เป็นไปได้ใน `meta.warnings[].likely` (`provider_error`, `no_data`, `history_ends_early` พร้อมวันที่ราคาล่าสุดใน `last_close`, `gap_in_history`) spin-off ตรวจไม่ได้เลย (ราคาที่ตกลงจะถูกนับเป็นขาดทุนจริง) |
| ปันผล | ไม่รวม (ผลตอบแทนเป็นแบบราคา ทั้งพอร์ตและดัชนี) |
| sector | Finnhub industry ไม่ใช่ GICS |
| ตารางบันทึกผลคำนวณ (calculation snapshot), ราคาดัชนีและ corporate actions ใน DB | ยังไม่มี: ดึงสดและแคชในหน่วยความจำ จึงตรวจย้อนหลังและทำซ้ำผลเก่าไม่ได้ |
| พอร์ตจริง | ยังไม่รองรับ: ปัจจุบันเป็นพอร์ตจำลองเท่านั้น |
| ช่วงเวลา | 1 ปีเท่านั้น |
| ความล่าช้าของข้อมูล | ราคาปิดรายวัน ผลสะท้อนหลังตลาดปิด ไม่ใช่เรียลไทม์ |
